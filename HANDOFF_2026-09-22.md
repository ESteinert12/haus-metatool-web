## 3. The `/api/pg/query` situation

Restored as an admin-gated passthrough (any SQL + params, requires `req.session.user`) rather than replacing it with purpose-built routes — this was a deliberate scope decision (confirmed with Erik) because `pgQ()` is called from 371+ sites in `index.html` and a real replacement is a large, multi-session project, not a stopgap-week fix.

What this means going forward: the endpoint works and is no longer open to the public internet, but it's still "any logged-in admin can run any SQL" — a broad trust boundary, not a properly scoped API. The real fix (purpose-built endpoints per feature, removing raw SQL passthrough from the client entirely) is still on the table as future work and hasn't been scoped yet.
